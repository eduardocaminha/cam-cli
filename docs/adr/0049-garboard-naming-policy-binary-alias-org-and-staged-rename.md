# ADR 0049: Garboard naming policy: product name, binary, alias, org, and staged rename

## Context

ADR-0045 renamed the product cam-cli to CAM Runtime as a display-only rebrand. Its Decision section did not defer the command name: it decided to leave the `cam` command, config/state directories, and `CAM_*` env vars unchanged. The only clause ADR-0045 actually deferred was the GitHub repo / local directory rename, to a separate operator-driven step with a coordinated fixture sweep. This ADR revisits and supersedes that decided, not deferred, command-name clause: whether the product's identity, and eventually its command surface, is called something other than cam. The naming decision was run as a dedicated research cycle (epic CAM-415, "naming e posicionamento pre-launch"), separate from the display-only rebrand ADR-0045 already shipped.

The process ran five rounds: a battery of roughly 110 candidates across four rounds of web research, indicative trademark screening, and a deterministic namespace sweep (DNS/RDAP across the `.dev`/`.io`/`.sh`/`.com` domains, npm, crates.io, PyPI, and the GitHub handle) run against each finalist, followed by a fifth, live-measured round on 2026-07-25 that re-verified the finalists and killed the round 1-4 champion.

That champion was GAMBREL: the carpentry/butchery frame a piece of meat or timber is held in while it is worked and inspected, chosen for its metaphorical fit with deterministic supervision holding an agent's work to spec until it passes verification. GAMBREL was demoted after the live-measured round on 2026-07-25 produced its own kill evidence: the GitHub org creation form reported "already taken" while the API returned 404 for both the org and the bare user (a tombstone: an account that is deleted or blocked, invisible to the API, but blocked at the creation form, which is the only real availability oracle since the API alone is insufficient); the search results for "gambrel" are dominated by "gambrel roof" (the American barn roof shape) and butchery hardware, unrelated products that would compete for the same search terms the CAM versus computer-aided-manufacturing SEO collision already forced on this product once; and the sound was rejected by the operator.

Garboard was the round 1-4 runner-up and the founder's original phonetic preference, carried forward with a near-clean namespace footprint. A garboard strake is the first hull plank laid against the keel: the structural-foundation metaphor is direct (the piece everything else is built on), and it shares the round 1-4 champion's phonetic profile (hard initial consonant, two syllables, concrete trade-craft sound) without the champion's SEO and tombstone problems.

Garboard was not chosen in isolation. The wider `-board` family was searched and killed candidate by candidate on the same live-measured round: `freeboard` (a real product with 6,503 GitHub stars), `switchboard` (a real product with 282 stars, npm name taken), `gateboard` (GitHub org taken, plus an existing GateBoard One hardware product), `aboveboard` (org and npm both taken), `pegboard` (npm taken), and `larboard` (weak metaphor, GitHub user taken). Garboard is the one member of that family that came back clean.

## Decision

The product is named **Garboard**. This ADR records the complete naming policy and supersedes the command-name clause of ADR-0045's Decision, as of the launch-packaging stage of the staged rename plan below (install compatibility for existing `cam` installs is preserved via the legacy symlink); it does not supersede a "naming-deferral clause", because ADR-0045's Decision did not defer the command name, it decided it ("Deliberately leave the cam command, config/state directories, CAM_* env vars ... unchanged"). ADR-0045's one real deferral clause, the GitHub repo / local directory rename to a separate operator-driven step with a coordinated fixture sweep, is untouched by this ADR and remains open: this docs-only cycle neither decides nor renames the GitHub repo or local directory. This ADR does not touch, and explicitly reaffirms, ADR-0045's display-only rebrand doctrine (the product name changes at the display layer; internal contracts stay `cam` until the staged rename plan below reaches them).

**Product name and binary.** The product is Garboard. The canonical binary name is `garboard`: what the world sees, speaks, and eventually installs.

**Typed alias.** The single typed alias is `gar`. The alias is typed, not spoken: it exists purely to save keystrokes at a shell prompt, never as a name the product is called out loud. Two alternatives were considered and rejected: `garb` (rejected for being longer than the four-character alias it was competing against, with no compensating benefit) and `gbd` (rejected as a classic `gdb`, the GNU debugger, typo: a user who fat-fingers `gdb` would land on a different tool by accident). `gar` was verified on 2026-07-25 against three collision classes: no `PATH` collision with an existing command, no man page entry, and no Homebrew formula of that name.

**Legacy symlink.** `cam`, the name this product has run under through ADR-0045, is demoted to an undocumented legacy symlink: it keeps working on machines that already have it, but it is not part of the public product surface, is not documented, and is not the name given to new installs.

**Canonical GitHub org.** The canonical GitHub org for launch is `garboard-run`. As of 2026-07-25 the org creation API returned 404 (available), which is the correct order of verification for a fresh org (unlike the GAMBREL tombstone case above, a 404 with no prior tombstone signal is the expected shape of a genuinely free name). `garboard-run` must be locked via the org creation form, the only real availability oracle, before any public announcement uses the name: an API 404 alone is not proof the name will still be free when someone acts on it. As of the same date, the bare `github.com/garboard` user handle is squatted by a dormant account created in 2016 (zero repositories, no bio), which is why the org, not the bare user handle, is the canonical namespace; and the `garboard` package name is free on npm. All of these namespace facts are point-in-time and expire: they must be re-verified immediately before the packaging step below actually claims them, not treated as a standing guarantee from this ADR's date forward.

**Staged rename plan.** The rename is staged, not immediate:
- Now (this cycle): docs-only. This ADR, `docs/positioning.md`, and any prose referencing the product name use Garboard. No code, template, build script, or binary is renamed.
- At launch packaging: the binary is renamed to `garboard` with the `gar` alias created by the installer, as a distribution item of launch readiness, not before.
- Never: internal contracts never rename, at any stage. This includes `CAM_*` environment variables, `.cam-*` state files, the `tmux -L cam` socket, `/cam-*` slash commands, and sentinel strings (`CAM_*_STATUS`). These are invisible contracts baked into running installs, on-disk state, and deterministic git history; renaming any of them is pure downside with no user-facing upside, which is exactly the reasoning ADR-0045 already applied to the display-only rebrand. This ADR extends that same reasoning to the product name change: the display layer moves, the internal contract layer does not, on both rebrands.

**Alternatives considered.** Beyond GAMBREL (demoted above) and the killed `-board` siblings, the process produced a ranked reserve list in case Garboard's namespace position changes before packaging: Gateship (bare user and npm free, on-thesis "gate to ship" semantics, but an invented compound word with an active neighbor, `gateship-one`, at 256 stars), Puncheon (the punch that stamps a certification mark, clean namespace except the GitHub handle), Laudo (a formal expert verdict, two syllables, clean YC-pitch cadence, but PyPI and the GitHub handle are taken), and Chancela (a perfect four-for-four namespace sweep, rejected for three syllables and ambiguous English pronunciation on a pitch stage). None of these are adopted; they exist so a future namespace collision on `garboard` has a pre-vetted fallback instead of restarting the search from zero.

This decision clears the three ADR admission gates. It is hard to reverse: once `garboard-run` is claimed, npm and domain registrations follow, and public-facing material (Substack, README, Product Hunt/YC materials) is written against Garboard, reversing costs real namespace and rewrite work, the same class of cost ADR-0045 was written to avoid paying twice. It is surprising without context: a reader who only knows ADR-0045 said the rebrand was display-only and decided to keep the `cam` command unchanged would not expect a second, product-identity-level name change to land on top of it, or expect `cam` itself to end up demoted to an undocumented symlink. It reflects a genuine trade-off with real alternatives: GAMBREL was the measured four-round winner and was killed only after a live re-verification produced disqualifying evidence, and the `-board` family and the ranked reserves show the alternative space was actually searched, not skipped.

## Consequences

Every future reference to the product in docs, positioning material, and launch content says Garboard; the running binary, its environment variables, state files, socket, slash commands, and sentinels all continue to say `cam` until the launch-packaging step above executes. That mismatch is intentional and mirrors the mismatch ADR-0045 already created between the CAM Runtime display name and the `cam` internals: this ADR adds a second display-layer name on top of the first without collapsing either mismatch early. Contributors who see `cam` in the codebase alongside "Garboard" in the docs must consult this ADR, the same way ADR-0045 already asks them to.

`docs/positioning.md`, the README differentiation section (CAM-331, out of scope for this ADR), and any build-in-public content (CAM-417) are written against Garboard as the settled product name; they do not need to re-litigate the naming decision, only cite this ADR.

The `garboard-run` GitHub org, the `garboard` npm package, and the `.dev`/`.io`/`.sh` domain registrations are operator ceremonies outside this docs-only cycle: the availability facts recorded here expire and must be re-checked at the moment those ceremonies actually run, not assumed still true from the 2026-07-25 verification date.

Binary, template, build-script, and slash-command renames stay out of scope until launch packaging picks up the staged plan above; a future ADR is only needed if that plan changes, not to execute it.
