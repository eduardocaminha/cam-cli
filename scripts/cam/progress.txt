Populated by implementers as reusable patterns emerge during stories.
Durable patterns carried across cycles:

- **Bun runtime**: always `Bun.spawn`/`Bun.$`/`Bun.file` over `node:child_process`/`fs` per project CLAUDE.md.
- **Permission mode**: never register a `--permission-mode` CLI flag on any subcommand,
  enforced by `test/no-permission-mode-flag.test.ts` (greps `index.ts` and `src/commands/`).
- **Tests**: `bun test` from repo root; test files mirror source under `test/`.
- **Conventional commits**: `feat:`, `fix:`, `chore:`, `refactor:`, `docs:`.
- **noUncheckedIndexedAccess**: tsconfig has `noUncheckedIndexedAccess: true`. Array indexing returns `T | undefined`; always guard with `?? fallback` or a justified non-null assertion.
- **Regex capture groups**: `match()` capture groups are `string | undefined` under strict+noUncheckedIndexedAccess; always use `?? ''` fallback.
- **Bun.spawn detached option**: `detached?: boolean` is in `bun.d.ts` (calls `setsid()` on POSIX) but the docs webpage omits it. Check `node_modules/bun-types/bun.d.ts` for the full option surface. Pair with `proc.unref()` and `stdio: ['ignore','ignore','ignore']` so the parent does not wait on the child.
- **tmux argv tests**: cam shells out to tmux via injectable spawn fns; unit tests assert the argv shape (new-session / split-window / has-session / send-keys / kill-session / select-pane), they do not spin a real tmux server. Follow this pattern for the cam-run-workspace cycle.
- **Ink screens**: success/failure is signalled by the glyph (accent check / destructive cross), never by divider color. Render and look at real output; do not trust header comments (lessons.md 2026-06-05).
- **No em-dash in persisted .md**: use commas, colons, parentheses, or periods.
- **src/tmux/session.ts is the canonical session module**: projectSessionName, ensureProjectSession, openPaneInSession, isInsideProjectSession all live here with injectable SpawnFn. Do not duplicate session logic in command files; import from this module instead.
- **isInsideProjectSession uses CAM_SESSION env tag**: because $TMUX_PANE only contains a pane index (not the session name), callers must set CAM_SESSION=<sessionName> when spawning claude inside a session for reliable inside-session detection.
- **`bun test` green is NOT proof of type-safety**: the test runner passes even when `tsc --noEmit` would fail. Always run `bun run typecheck` separately and trust its exit code before claiming the gate passed. US-008 shipped 6 TS2322 errors in `test/attach-hint.test.ts` with a fully green suite (caught at the next pre-flight, fixed in a follow-up). Common trap: a `captureStdout(() => runX(...))` helper typed `() => void | Promise<void>` rejects callbacks returning `Promise<number>`; widen such helpers to `() => unknown`.
- **tmux shell-command form**: single arg to split-window/new-window goes through `/bin/sh -c` (shell injection risk). Multi-arg form execs directly (bypasses shell). Change `openPaneInSession(session, cmd: string)` to `openPaneInSession(session, cmdArgv: string[])` and spread the argv as separate trailing args after a `--` separator. Do NOT join argv before passing; user-supplied free text (issue descriptions, etc.) must stay as discrete elements.
